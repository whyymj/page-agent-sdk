## 假设结论

**H15(双 return 完整性)——证伪,当前无漏。** ChatSdk 接口 60 项与 _createChatSdk return(:2175-2356)逐一对上;AgentCore 接口 59 项与 buildCore core 字面量(:1293-1830)逐一对上。两个字面量分别受 `: ChatSdk` 返回类型 / `: AgentCore` 标注的 tsc 结构检查,**src 内部漏项编译器直接抓**——2.38 getActiveSubagents 型事故在 src 层已不可复发,风险仅存于 d.ts↔src 轴(见 H7)。残留小项:AgentCore.send 签名窄于实现(:593)、debugLogs getter 无 init 防御(:2204)。

**H7(类型门禁缺口)——证实,且有活体实例。** 三道门实际覆盖:①test:exports(tests/exports-consistency.mjs)= 正则比对 src/core/index.ts ↔ types/*.d.ts **导出名集合**,只抓符号缺失/多余;②test:types(tsconfig.test.json include 仅 types/*.d.ts + types.test-d.ts,**不含 src**)= d.ts 自洽 + 手工 Pick/Extract 抽样,**从不与 src 同编译**;③src 全量 tsc = src 内部一致。盲区 =「对外 d.ts 结构 ↔ src 实现结构」永不互相比对:d.ts 删方法/漂签名只能等运行时 TypeError。活体:send options d.ts 只剩 {mission?}(types/index.d.ts:870),src 承诺的 per-call interceptors/maxAutoRetries 类型不可见;字段级 Pick 仅锁 37/60,事故主角 getActiveSubagents 恰不在锁定集。修法:d.ts↔src 接口互 assign 的 test-d 断言 + Pick 补全。

**H23(MCP 超时)——证实,sse/websocket 比假设更糟。** connectMcp(mcp/client.ts:94-101)无 SDK 层超时:协议请求(initialize/listTools/callTool)受 MCP SDK 默认 60s 超时保护,但 **transport 握手**(websocket.js:21 / sse.js:97 裸等 onopen)无超时 → 黑洞端点永久挂起 → allSettled(:1994)不 settle → initDone 不 resolve → mount/send/switchSession/batch 全挂,无 warn 无事件;createAgent 排 MCP 段之后(:2016),一个坏 server 锁死全部功能。http 不永挂但 N server 可拖 60s×N。McpServerConfig 无 timeout 选项,集成方无法自救。

**H11(shareContext 双实例)——证实,无跨实例屏障。** ①runSerial 每实例私有(:2173)而 core 共享(:2066-2073)→ 双实例 send/switchSession/batch 可并发写同一 messages/agent;②一实例 switchSession/resetSession(:1499/:1549)splice 共享 messages、重置 vfs/todos/mission/focus,**不 abort 另一实例活跃流**(P1-b 修复仅各实例自己 useChat 层)→ ghost 轮把输出写进新 sessionId;③unmount(:2147)无条件 resolveConflict('keep_external'),单方面了结另一实例活跃写正等待的冲突;④refCount 归零 release 关 mcpClosers + store.dispose(:1583-1596),流在途则持久化落空、MCP 工具调用报错。

## 其余范围项核实(R6 焦点)

- **middlewareStack 装载序与 CLAUDE.md 一致**:dataHint10→usageHints20→todos30→skills40→vfs50→summarization60→memory70→permissions80→checkpoint90→humanConfirm100→approval110→verify120→subagent130→subagents140→augmentSystem150→Infinity 声明序(mission/workingMemory/focus/resourcesPin/context-inspector/用户 middleware/budget/sdk-events),符合「usageHints→todos→skills→vfs→summarization→memory→permissions→verify→subagent→用户自定义」缩写序 + pin 段 Infinity 声明序约定;sdk-events 不声明 priority 靠构造位置尾随(middlewareStack.ts:25-27 注释)。
- **dedupeTools 覆盖语义**:后注册覆盖先注册 + collisions warn(toolRegistry.ts:36-48);装配序 builtin→user→action→humanConfirm→checkpoint→focus→mcp→skill(createChatSdk.ts:1013-1022),skill 最后可覆盖全部;addTool 同名覆盖 + warn(:1609-1620)。
- **rebindTools 时机**:setTools/addTool/removeTool/setLlm 即刻重建 allTools+rebind(createAgent.ts:828-842);进行中轮次下一次模型调用即用新集;已发出的 tool_call 执行时按名实查 allTools(createAgent.ts:505),查不到回灌「工具不存在」recoverable,不崩。
- **events 发射完整性**:stream 包装层转发全部流式事件(round_start/reasoning/text/tool_call/tool_result/done/error/subagent/approval_request)但受 Finding 2 条件 bug 制约;approval_request 经 emit 统一过滤(events.ts:23),UI 内部 handler 收未过滤版(确认条需要);中间件层 data_change/usage/message_update 在 send/stream 双路径均发;send(invoke)路径无流式事件(符合文档),有 error(fatal emit+throw :1458)+ AUTO_RECOVER_RETRY(:1454);其余发射点:session_restored(init/switchSession/resetSession)、context_trimmed(trim)、BUDGET_EXCEEDED(budget 中间件)、trace(onTrace)、BATCH_TASK_FAILED(batch)、focus_chip_click(UI chip)。
- **headless mounter 缺失降级**:路径完整(createChatSdk.ts:2108-2115,ui!=='false' 且无 mounter → console.warn 降级 + installFlush 仍安装)。
- **actions 异常隔离**:正确(actions.ts:47-54 run 抛错回灌错误串不崩 agent;非法名跳过 + warn :40-42;无 params 默认 z.object({}))。defineTool 无隔离但错误经 coreExecTool catch 转 recoverable 回灌,符合契约。

## 总评

双 return 当前完整且受 tsc 结构检查保护,真正的结构缺口在 d.ts↔src 无人看管的轴线上(send 签名活体漂移 + 字段门禁只锁 37/60);MCP sse/websocket 握手无超时是唯一可致整体永久挂死的 P1,hook 收流式事件的条件分支是低成本必修 P1;shareContext 缺跨实例串行与活跃流屏障,建议四项同列下个发布修复清单。
