## H 假设证伪结论

- **H19(成立)**:子工具即主 allTools 的同一对象实例(subagent.ts:234-237 自主 `allTools` getter 筛选、零拷贝),闭包=主 dataOps controller。子 read 更新共享 `lastReadHash`(dataOps.ts:706)→ 父 autoLock 基线被污染,危害方向是**静默放行**(父陈旧写覆盖子/外部变更)而非误冲突;子写入共享 snapshots(dataOps.ts:157-159/231-233)→ 父 restore 可回退/撤销子成果;audit/脏标记同样混流。装配证据:createChatSdk.ts:1069 `allTools: () => allTools` → subagent.ts:231-237。
- **H20(成立)**:pool.ts:27-35 无单项容错,`Promise.all` 任一 reject 即整体 reject;subagent.ts:380-401 归并仅在全成时产生,单失败→成功结果全丢、归属不可辨,且在途兄弟不取消继续孤儿执行。
- **H21(成立,机制更重)**:非 LRU 淘汰问题——子 agent 无 vfs middleware,`state.files` 为每次 stream 新建空对象(createAgent.ts:578/state.ts:112),子 offload 写入该一次性 map(createAgent.ts:510-517),而子的 vfs_read 是主 vfsStore 实例 → **回读必然 404、原文实际丢失**;protectedRefs 注入时机(createChatSdk.ts:1569 仅父 stream 入口)是次生问题。
- **H25(部分成立)**:jsonPath 形态维度覆盖完整(jsonPath/patch.jsonPath/patches[].jsonPath/path 全提取,整体 set 与无 path 的 merge/append 拒绝,前缀边界 `components.10`≠`components.1` 正确,sec-44 有单测);但**工具面**有盲区:draft_commit 永被拒(死条目)、eval_script/resource_update 经 allowedTools 带入时绕过 guard 可写。
- **H28(成立)**:子 agent 无 sdk-events 中间件 → token 不计 usage(createChatSdk.ts:717-743)→ tokenBudget 闸漏算;runSubagent 无任何超时,子挂死→父无限等;timeBudget 仅在父 wrapModelCall 检查(budget.ts:39-60),拦不住在途子。

## 总评

主×子隔离在**上下文/消息层**做得扎实(task 唯一输入 subagent.ts:310、结论唯一输出且回灌经父 offload 闸 createAgent.ts:511、spawn 物理切断 :247、focus 继承 :249-252 均核实无串台),但**共享闭包状态层**完全敞口——dataOps controller(乐观锁基线/快照栈/冲突挂起/审计)与 vfs 存储无隔离无归属,叠加 spawn 自授工具绕过 approval/permissions、子消耗不计预算,构成主×子协同的全部实质风险面;5 项 P1 建议下个发布修复。
